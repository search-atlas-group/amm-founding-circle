# SEO fulfillment implementation — gated mission plan

**Origin:** mastermind session, segments 713–749  
**Status:** draft / review required before execution  
**Pilot target named in session:** one approved pilot client; verify authorization and current account identity before any data pull.

## Outcome

Turn the agency’s SEO service skills into a coherent, owned, reviewable fulfillment system, then dry-run the system on one approved test client before any publishing or broad rollout.

## Phase 1 — Skill inventory and service buckets

Map the relevant skills into the team repository and assign each to a service bucket:

- CRO audit
- Technical SEO audit
- Content planning and writing
- Topical map / content plan
- Authority building and link building
- Press release planning
- GBP optimization / automation
- Other local or paid-media fulfillment gaps discovered during review

**Deliverable:** a versioned skill-to-service map with one owner per bucket.

## Phase 2 — Dry run on the approved pilot

Run the analysis-only versions of the skills against the approved pilot account. Capture inputs, outputs, gaps, and human review notes. Do not publish press releases, deploy changes, or send client-facing material as part of this phase.

**Deliverable:** a mission report showing what each skill would do, what evidence it used, what it could not access, and what a human must review.

## Phase 3 — Review and refinement

The commander and fulfillment owner review the mission plan and dry-run report. Narrow the scope, correct the service map, add missing skills, and define the exact execution gate.

**Deliverable:** approved v1 implementation plan and card sequence.

## Phase 4 — Controlled execution

Only after explicit approval, execute the smallest useful slice. Verify output, document the review, and decide whether the slice is safe to turn into a repeatable skill or automation.

## Definition of done

- [ ] Skills are mapped to service buckets.
- [ ] One owner is named for each bucket.
- [ ] Pilot inputs and account identity are verified.
- [ ] Dry-run outputs are saved and reviewable.
- [ ] External writes remain off until approval.
- [ ] The first approved execution has evidence and a rollback / correction path.

## Safety boundary

This plan is analysis-first. It must not publish, deploy, alter a client account, or send client-facing updates merely because a skill can technically do so. The review gate is part of the mission, not an optional courtesy.
