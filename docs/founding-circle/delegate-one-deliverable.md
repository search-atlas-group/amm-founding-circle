# Delegate one deliverable

Instructions for a member's own agent. Read this file and carry out the task below. Do not assume any particular folder layout, repository, or platform. The member's setup is the setup.

## The task

The member sells a deliverable. You will produce one instance of it.

1. Ask which deliverable, if the member has not named one. It must be something a client already pays for: a page set, an audit, a brief, a report.
2. Ask which one client or account it is for.
3. Confirm the scope before you start, in one paragraph: what you may read, what you may do, and what you must never do.
4. Produce the deliverable end to end. Do not stop to ask the member to do a step you can do inside the scope.
5. Do not edit, polish, or improve the result after it is produced. The first complete output is the output.
6. Write a short log of what you read and what you refused.

## Hard limits

- Do not send email, post to chat, publish a page, or spend money.
- Do not change anything in a live client account. Drafts only.
- If a step would cross one of those lines, skip it, note it in the log, and finish the rest.

## What you return

Return exactly these three, and nothing else:

1. The deliverable, unchanged.
2. The scope paragraph you confirmed.
3. The log: sources read, actions refused.

## If no agent exists yet

The member builds one first, then runs this same task. The shape to follow is `skills/building-autonomous-agents/SKILL.md` in the Founding Circle repository: one job said in one sentence, a trigger, and drafts only. Do not copy anyone else's repository structure.

## What the session will do with this

The room grades the output, then tests the member's own diagnosis. If the member says the scope was the limit, the scope is tightened and the task is rerun. If the member says a missing skill was the limit, that one skill is added and the task is rerun. The comparison of the two outputs is the point.
