Memory + Judgment Architecture

A system design for combining QMD local memory with JEV structured judgment. QMD supplies the right history. JEV decides what the workflow should do with the current item. The application enforces the decision, and the execution agent acts only after both layers have done their work.

The design principle: retrieve context before making a decision.

Without memory, agents guess what matters. Without judgment, every message reaches the expensive agent. Together, the system recalls the relevant history, makes a narrow decision, and routes only the work that deserves deeper reasoning.

2 · What each component owns

QMD owns memory

QMD answers: “Which of my previous notes are relevant?”

  • Local markdown notes and decisions
  • Keyword search first, semantic search when needed
  • Automatic recall before each prompt
  • Pointers first, full notes only when relevant
  • Offline, no per-query API charge

JEV owns judgment

JEV answers: “What should the system do with this text?”

  • Narrow yes/no, choice, or score questions
  • Reply, route, review, ignore, allow, or block
  • Probability and choice distribution for tuning
  • Runs explicitly through the TypeSage API
  • Never treated as permission for sensitive actions by itself

The application owns control

The application answers: “What threshold and permission rule applies?”

  • Thresholds such as reply ≥ 0.70
  • Review bands for ambiguous scores
  • Deduplication, rate limits, and access control
  • Human approval for external or privileged actions

The agent owns execution

The agent answers: “How should approved work be completed?”

  • Draft the response or perform the approved task
  • Use the QMD notes as grounded context
  • Verify the result before claiming completion
  • Never decide routing and execution in one opaque step

QMD savings are measurable. JEV savings are a scenario until instrumented.

  • QMD cost: local compute, approximately 100ms and under 700 bytes of pointers per prompt, with no per-query API charge.
  • JEV cost: depends on TypeSage usage, question count, model, and routing volume. Instrument JEV responses and provider billing before claiming a dollar figure.
  • Combined upside: QMD can reduce repeated context and JEV can prevent low-value items from reaching the expensive execution agent. The second saving is an explicit measurement target, not a claimed result.
