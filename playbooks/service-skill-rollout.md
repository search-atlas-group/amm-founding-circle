# Service-skill rollout playbook

Use this when a team has a skill pack and wants to turn it into a reliable client-delivery process.

## Sequence

1. **Map:** list each service bucket, skill path, input, output, owner, and review gate in `templates/service-skill-map.md`.
2. **Brief:** create a mission plan with `templates/mission-brief-template.md`.
3. **Pilot:** choose one authorized client or a fictional/redacted fixture. Verify identity and scope.
4. **Dry run:** run analysis-only skills and save inputs, outputs, unknowns, and review notes.
5. **Review:** the fulfillment owner checks suitability and quality. No publishing, client messaging, GBP change, or press release occurs here.
6. **Scale:** after approval, execute the smallest useful slice, attach evidence, and decide whether the process is ready for recurring rollout.

## Failure handling

Missing skills are gaps, not installed capabilities. Missing client access is `BLOCKED`, not permission to guess. An output that is not reviewed is a draft, not a client result.

## Non-overlap

`share-your-foundation` packages and installs a shared foundation. `client-onboarding-os` sequences an engagement. `division-operating-model` governs training and rollout. This playbook connects those assets for one service pilot.
